# ADR-001: Monorepo vs Multi-repo

## Estado

Aceptada (propuesta para el MVP).

## Contexto

El MVP necesita:

- Frontend React + Tailwind + Vite.
- Backend Node + Express + TypeScript.
- Skeleton Python (`services/cad-worker`) con `pyproject.toml` y entrypoint CLI.
- Lint/format coordinados para TypeScript y Python.
- Levantamiento local reproducible (con scripts y/o `docker-compose`).

## Decisión

Adoptar un **monorepo** para el MVP.

Estructura sugerida:

- `apps/web`: Frontend React + Tailwind + Vite.
- `apps/api`: Backend Node + Express + TypeScript.
- `services/cad-worker`: Skeleton Python con `pyproject.toml` y entrada CLI.

## Consecuencias

Positivas:

- Un único punto de entrada para scripts del repo (`lint`, `format`, `dev`).
- Compartición simple de configuraciones base (p. ej. `tsconfig.base.json`).
- Menos fricción para cambios transversales.

Negativas / trade-offs:

- Riesgo de crecer en tamaño si no se controla `node_modules`/artefactos.
- Se requiere disciplina de workspaces/configuración.
